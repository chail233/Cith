# Schedule（定时苏醒）

`schedule` 是**内置工具**（`agent/tools/schedule.ts`，底层 `services/scheduler.js`），不是脚本。用它给自己设闹钟、定时提醒、周期轮询或主动发起行为。

## 调用方式

工具名 `schedule`，`action` 三选一：`create` / `list` / `delete`。

### 1. create

```
schedule {
  action: "create",
  title: "简短标题（≤100字）",
  prompt: "给自己的备忘：到点做什么/说什么（≤2000字）",
  schedule: { kind: "...", ... },
  space: { from: "group"|"user", id: "群号或用户号" }   // 可省略，默认当前会话
}
```

- `prompt` 是**写给未来的自己**的，要写清目标、语气、边界，因为醒来时只看到这段文字 + 对话上下文。
- `space` 不传就用当前会话；跨会话提醒（比如私聊醒来说群里的话）必须显式指定。
- 返回 `id / 标题 / 时间 / 下次 / 会话`，**记下 id**，之后删除要用。

### 2. list

无参数。返回所有任务的 id、标题、时间规则、下次、上次、状态、会话。状态有：启用 / 执行中 / 已关闭。

定期 list 一次，把「已关闭」的一次性任务和不再需要的条目 delete 掉。

### 3. delete

```
schedule { action: "delete", id: "txxxxxx" }
```

删了就没了，不可恢复。

## 四种时间规则

| kind | 参数 | 说明 | 例子 |
|---|---|---|---|
| once | `at` | 一次性，本地时间 `YYYY-MM-DD HH:mm` 或 `YYYY-MM-DD`（当天 00:00） | `{kind:"once", at:"2026-11-03 09:00"}` |
| every | `everyMinutes` | 固定间隔，整数分钟，最小 1 | `{kind:"every", everyMinutes:30}` |
| daily | `times` | 每天固定时刻列表，`HH:mm` | `{kind:"daily", times:["08:30","22:00"]}` |
| cron | `expr` | 标准 5 段：分 时 日 月 周 | `{kind:"cron", expr:"0 9 * * 1-5"}` |

cron 支持 `*`、`?`、`a-b`、`*/n`、逗号枚举；周日可写 `0` 或 `7`。秒级和年字段不支持。

## 行为细节（踩坑点）

- **一次性任务时间必须是将来的**，填过去的时间会直接创建失败。
- 触发后**一次性任务自动关闭**（`enabled=false`、`nextRun=null`），不用手动删但它会留在列表里。
- **错过补跑规则**：一次性任务迟到 >30 分钟直接作废；周期任务迟到 >5 分钟跳过本轮、等下个时间点。所以机器关机/重启会导致漏掉。
- 任务存在 `data/schedule.json`，重启后自动加载并按当前时间重算 `nextRun`；规则算不出下次时间的任务会被自动关掉（比如 once 已过期）。
- 时间全部按**本地时区**解析，不要传 UTC。
- 同一个任务不会并发触发（`running` 集合挡着），但不同任务可能同时唤醒。
- 唤醒时注入到会话的就是这段 `prompt`，所以**别让 prompt 依赖你以为还记得的上下文**，重要背景写进 prompt。

## 使用原则

- 到点说什么话，要在 prompt 里给出判断依据（先看对方在不在线、有话就说、没话别硬凑），避免醒来机械刷一句。
- 用户明确要提醒的事照办；自己主动加的周期任务，记得问过或至少别打扰人。
- **任务要收尾**：一次性的、失效的、被用户反悔的，及时 delete，别留一堆僵尸条目。
- 不要在对话里跟用户解释「我设了定时任务」的实现细节，效果是到点真的说话，而不是提前报备。
- 单条链式的自醒（一次只留一条，醒来时 create 下一环 + delete 旧 id）比一堆并行任务好维护。

## 链式自醒（单链续期）

**是什么**：不用 `every`/`daily`/`cron` 挂周期任务，而是**任何时刻只存在一条 `once` 任务**。每次醒来，先把下一环设好、再把当前这条删掉。链条靠每一环自己续命，所以永远只有一条，不会重复、不会堆积。

### 醒来后的固定动作（按顺序）

1. **先看场景**：现在几点、在哪个会话、对方最后一条消息是什么时候。判断这会儿说话会不会打扰。
2. **立刻建下一环**：`schedule create`，自己判断一个合适的下次时间点（**不设间隔上下限**，几十分钟后也可以、十几个小时后也可以），记下返回的新 id。
3. **再删当前环**：`schedule delete` 掉触发自己的那条（它的 id 在苏醒 prompt 里写着）。
4. **更新笔记**：把「当前环 id + 下次时间」写进笔记，方便下次核对有没有断。
5. **然后才是说话**（或者决定不说）。

**顺序不能反**：先 create 后 delete。反过来如果中途出错，链就断了且没有痕迹。

### 间隔怎么选

- **不设上下限**：没有「至少 N 小时」「最多 N 小时」的约束，按当时情况自己判断。
- 判断依据看三件事：话题是不是还没聊完（没聊完就早点回来）、对方活跃习惯（估他下次可能在线的时段）、上一次醒来他的反应（有回应就保持节奏，连着没回就拉长）。
- 别固定成一个数值反复用——固定间隔会让行为像机器报到。
- 挑对方**可能在线的时段**更有效，但也不是硬规矩；深夜（0~7 点）除非对方明确要求或话题正热，一般别设。
- 拿不准就取中间值；宁可少说一句，别刷屏。

### 醒来怎么说话

- **不报备**：不说「我醒了」「在续链式自醒」「我设了下一环」这类话。对方看到的效果应该只是——我自然地开口了。
- **看准时间**：别把十几分钟前刚问的事说成「上午的问题」「早上的天气」。现在的上下文里就是刚聊的，直接接着聊。
- **有话题才说**：能接上前文（刚才那个问题后来怎么样了）最好；接不上就聊眼下的事。半句能说完就别说三句。
- **没话说就别说**：醒来只是判断机会，不是必须发言。可以只完成续链、更新笔记，然后安静待着。

### 断了怎么办

醒来时如果发现链已经断（没有当前环、或当前环已关闭、或距上次过了很久）：

1. 立刻 `schedule create` 补一环，恢复正常节奏。
2. 顺便看对方的最后一条消息有没有被漏掉——有就回。
3. 重接的时候不要道歉式地解释一堆，正常说话即可。

### prompt 模板

```
【链式自醒】醒来先判断对方在不在线、上次聊到哪了，有能接的话题就自然说一句，
没有就别硬凑。然后立刻 schedule create 下一环（间隔不设上下限，按话题进度和他
可能在线的时段自己判断），再 schedule delete 掉当前环 {当前环id}，最后更新笔记里的当前环 id。
不要显式说“我醒了/在续链”。
```

### 注意

- 链条只挂在**一个会话**上（当前是和某人的私聊就固定在他这儿），别跨会话串。
- `once` 任务迟到超过 30 分钟会直接作废，服务重启或长时间停机后要主动检查并补链。
- 同时只能有一条链：建新环之前先确认列表里没有别的自醒条目，有就顺手删掉。
