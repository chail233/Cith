# rememori 使用说明

> 基于 [GiorgioDotcom/rememori](https://github.com/GiorgioDotcom/rememori) v0.7.0（MIT）整理。
> 定位：**"the SQLite of agent memory"** —— 零依赖、纯 TypeScript 的嵌入式 Agent 语义记忆库，运行在任何有 JS 的地方（Node / Bun / 浏览器 IndexedDB），无需服务器。

---

## 1. 安装

```bash
npm install rememori
```

- 主入口：`import { Memory } from 'rememori'`
- 内置 embedder 工厂：`import { ollama, openai } from 'rememori/embedders'`
- 运行时零 dependencies（devDeps 仅 tsup + vitest）

embedding 是唯一外部能力，二选一：

```bash
# 方案 A：本地 Ollama（数据不出机器）
ollama pull nomic-embed-text

# 方案 B：任何 OpenAI 兼容 /embeddings 端点
```

## 2. 快速开始

```js
import { Memory } from 'rememori';
import { ollama } from 'rememori/embedders';

// path 三态：'./agent.rememori'（文件）| 'idb://name'（浏览器）| ':memory:'（易失）
const mem = await Memory.open('./agent.rememori', {
  embedder: ollama('nomic-embed-text'),
  minSimilarity: 0.5, // 相关性底线，见 §4.2
});

const id = await mem.remember('My server runs Debian on a Pi 4', {
  tags: ['infra'],
  importance: 0.9,
});

const hits = await mem.recall('what hardware is the server on?', { limit: 5 });
console.log(hits[0]?.text, hits[0]?.score);

await mem.close();
```

## 3. 典型 Agent 记忆闭环

官方示例 `examples/ollama-chat.mjs` 的标准流程（recall → 注入 prompt → 回答 → remember → 证据强化）：

```js
// 1. 召回：带上时间衰减，近期有用的记忆排名更高
const hits = await mem.recall(user, { limit: 5, halfLifeDays: 30 });
const context = hits.map((h) => `- ${h.text}`).join('\n');

// 2. 把记忆注入 system prompt，让模型回答
const answer = await chat(system + `\n\nThings you remember:\n${context}`, user);

// 3. 用户说的话也存下来
await mem.remember(user, { tags: ['chat'] });

// 4. 证据门控强化：只有"确实出现在回答里"的记忆才加权（推荐，防自反馈回路）
await mem.reinforceFromOutput(hits, answer);
```

## 4. API 参考

### 4.1 `Memory.open(path, options)` → `Memory`

| option | 类型 | 默认 | 说明 |
|---|---|---|---|
| `embedder` | `{ embed(texts): Promise<Float32Array[]> }` | 必填 | 唯一的扩展点 |
| `storage` | `StorageAdapter` | 按 path 推断 | 自定义持久化 |
| `extractor` | `EntityExtractor \| false` | 内置大写词启发式 | 实体抽取器；传 `false` 关闭图 |
| `index` | `'auto' \| 'hnsw' \| 'flat'` | `'auto'` | <1000 条精确扫描，超过自动建 HNSW |
| `minSimilarity` | `number` | `0` | 实例级相关性底线 |

### 4.2 `recall(query, options)` → `RecallHit[]`

排序公式：`(cosine + entityBonus + hardening) × importance × 0.5^(age/halfLife)`

| option | 默认 | 说明 |
|---|---|---|
| `limit` | 10 | 返回条数上限 |
| `tags` | — | 要求记录**同时携带**所有给定 tag（带 tag/日期过滤时强制走精确扫描） |
| `after` / `before` | — | 按 `createdAt` 过滤，epoch ms 或 ISO 串 |
| `halfLifeDays` | 不设=不衰减 | 时间衰减半衰期（天） |
| `minScore` | 0 | 最终分下限 |
| `minSimilarity` | 实例默认 | **原始 cosine 底线**，低于则丢弃——除非与查询共享实体。模型相关：nomic-embed-text 实测 ~0.5，MiniLM ~0.3 |
| `graph` | true | 查询侧实体抽取 + 共享实体加成（每个 +0.1，封顶 0.3） |

命中项含 `score`（综合分）、`similarity`（原始余弦）、`sharedEntities` 等字段。

### 4.3 `remember(text, options)` → `id`

`{ tags, importance(0..1, 默认1), meta, entities(显式指定则跳过抽取器), createdAt(导入/测试用) }`。空文本抛错。

### 4.4 反馈三件套

| 方法 | 作用 |
|---|---|
| `reinforce(id)` | 标记"真正被用上"：重置衰减锚点 + log 阻尼加权（每级 0.05×log2(1+n)，封顶 +0.15） |
| `demote(id)` | 负反馈（用了且错 / 矛盾裁决败方）：对称罚分，封顶 −0.15，**不动**衰减锚点；罚狠了记忆可直接掉出召回——这是有意行为 |
| `reinforceFromOutput(hits, output)` | 证据门控版 reinforce：纯文本判定（连续 token 串 ≥4 或 distinct 包含率 ≥0.6，且**数字一票否决**），返回被强化的 id 列表。刻意不用 embedding 比对，防止模型自报有用导致反馈回路 |

```js
const ok = await mem.reinforce(id);            // id 未知返回 false
await mem.demote(wrongId);
const used = await mem.reinforceFromOutput(hits, llmAnswer);
```

### 4.5 矛盾处理：`collisions(id, {threshold=0.8, limit=5})`

引擎只报告"异常接近"的记忆（近重复 / 更新 / 矛盾三态不明），**判定交给调用方 LLM**，再对败方 `demote()` 或 `forget()`：

```js
const newId = await mem.remember('We migrated to Postgres', { tags: ['db'] });
for (const c of mem.collisions(newId)) {
  const verdict = await llmJudge(newText, c.text);   // duplicate|update|contradiction
  if (verdict === 'contradiction') await mem.demote(c.id);
  if (verdict === 'duplicate')     await mem.forget(c.id);
}
```

### 4.6 实体图

```js
mem.entity('Giorgio')  // → { name, count, memories[], coEntities[] } 实体卡片
mem.entities(20)       // → 图中连接数最多的前 20 个实体
```

### 4.7 维护

| 方法 | 说明 |
|---|---|
| `forget(id)` | 删除（写 tombstone），返回是否存在 |
| `prune({ olderThan: '90d'\|ms, belowImportance })` | 批量清理，返回删除数；会重建索引 |
| `compact()` | 重写存储，折叠 tombstone 与重复写 |
| `get(id)` | 单条读取（不含向量，防御性拷贝） |
| `size` | 记忆条数 |
| `close()` | 关闭存储 |

## 5. 存储后端

| path 形式 | 适配器 | 格式 |
|---|---|---|
| 文件路径 | `FileStorage`（Node/Bun） | append-only JSONL，向量 base64，同 id 后写覆盖；`compact` 走 tmp+rename 原子替换 |
| `idb://name` | `IndexedDBStorage`（浏览器） | IndexedDB |
| `:memory:` | `InMemoryStorage` | 易失 |
| 自定义 | 实现 `StorageAdapter`（load/append/tombstone/compact/close） | — |

注意：**无文件锁，单进程假设**。多进程打开同一文件会交错追加，不安全。

## 6. MCP Server（给 Claude Code 等 Agent 直接用）

仓库内自带 `rememori-mcp`（npm 包名 `rememori-mcp`）：

```bash
ollama pull nomic-embed-text
claude mcp add rememori -- npx -y rememori-mcp
```

环境变量：

| 变量 | 默认 | 用途 |
|---|---|---|
| `REMEMORI_PATH` | `~/.rememori/memory.mem` | 记忆文件 |
| `REMEMORI_EMBEDDER` | `ollama` | `ollama` 或 `openai` |
| `OLLAMA_MODEL` / `OLLAMA_URL` | `nomic-embed-text` / `http://localhost:11434` | 本地端点 |
| `OPENAI_API_KEY` / `OPENAI_MODEL` / `OPENAI_BASE_URL` | — / `text-embedding-3-small` / api.openai.com | OpenAI 兼容端点 |
| `REMEMORI_MIN_SIMILARITY` | `0.5` | 召回底线；召回常空就调低 |

暴露工具：`remember` / `recall` / `reinforce` / `reinforce_from_output`（推荐优先用）/ `demote` / `collisions` / `get` / `forget` / `entities`。

## 7. 中文 / CJK 使用注意

库本身对 CJK 有两处已知短板，中文场景务必处理：

1. **实体抽取**默认是"大写首字母词"启发式（英文+意大利语），对中文完全失效 → 传入中文 NER / LLM 抽取器：

```js
const mem = await Memory.open(path, {
  embedder: ollama('bge-m3'), // 建议换中文友好的 embedding 模型
  extractor: {
    async extract(text) {
      return myChineseNER(text); // 返回 string[]
    },
  },
});
```

2. **证据门控**（`reinforceFromOutput`）按空格分词，未分段中文会整体成为一个 token，只有逐字精确复用才命中，改写/复述判 0 分 → 中文场景可先分词再喂，或改为手动 `reinforce(id)`。
3. `minSimilarity` 参考值随模型变化，换中文模型后需重新实测。

## 8. 性能参考（官方 bench，nomic-embed-text）

| 记忆量 | 精确扫描 | HNSW | recall@10 |
|---|---|---|---|
| 1,000 | 0.5 ms/查询 | 未启用 | 100% |
| 10,000 | 4.4 ms/查询 | 2.3 ms/查询 | 100% |
| 50,000 | 26 ms/查询 | 2.8 ms/查询 | 100% |

瓶颈提醒：`open()` 全量加载所有记录进内存；`collisions()` 是 O(n) 全扫。5 万条以上启动内存/时间线性增长，超大规模场景需自行分片（多个 Memory 实例）。

## 9. 已知限制汇总

- 单进程、无并发锁；崩溃安全性靠 append-only（最后一条写可能截断，重放容忍）
- v0.7.0，格式兼容靠 loader 默认字段兜底，无稳定性承诺
- 矛盾检测只测"邻近"，语义裁决必须外挂 LLM
- embedding 维度变更 = 旧向量全部失效，换模型需重嵌入（可用 `remember` 的 `createdAt` 选项做导入）

## 10. 本项目（Cith）的接入方式

| 环节 | 位置 | 说明 |
|---|---|---|
| 单例与生命周期 | `core/services/memory-store.ts` | `initMemoryStore()` 启动时 open（按 `memoryEmbedProvider` 探测本地 Ollama 或 OpenAI 兼容接口），`closeMemoryStore()` 退出时 close；初始化失败只 warn 降级，不影响对话 |
| 业务接口 | `core/agent/long-term-memory.js` | `addMemory()` / `addFacts()` → `remember()`，`searchMemory()` → `recall()`；写入统一走串行队列 |
| 写入时机 | `core/agent/recorder.js` | 中期概括被覆盖前，把上一批事实**逐条** `remember`（一条事实 = 一条记忆），不再整段写入 |
| 召回入口 | `core/agent/tools/get-memory.ts` | AI 调用 `get_memory` 时：传 `queries` 数组则每条语句各召回一次；不传或空数组则取最近几条消息里的有效文本（最多 5 条）逐条召回；所有命中合并去重、按相似度取前 `memorySearchTopK` |
| 会话隔离 | 不使用 tag | 所有记忆共用一个检索空间，召回走向量索引；不同群/私聊的长期记忆会相互串（当前已知取舍） |
| 配置文件 | `core/data/rememori/memory.mem` | append-only JSONL，已 gitignore；容器部署需挂 volume |
| 维护节奏 | `maintainMemoryStore()` | 启动时执行一次 prune + compact；之后每成功写入 `memoryMaintainEveryWrites`（默认 100，0 关闭）条再执行一次 |

配置项（`core/config.js`）：`enableLongTermMemory`、`memoryStorePath`、`memoryEmbedProvider`、`memoryOllamaUrl`、`memoryEmbedBaseUrl`、`memoryEmbedApiKey`、`memoryEmbedModel`、`memoryMinSimilarity`、`memorySearchTopK`、`memoryHalfLifeDays`、`memoryTimeout`、`memoryMaintainEveryWrites`。

embedding 提供方二选一：

- `memoryEmbedProvider: "ollama"`（默认）：本地 Ollama，配 `memoryOllamaUrl` + `memoryEmbedModel`（如 `bge-m3`），启动时探测 `GET /api/tags` 校验模型。
- `memoryEmbedProvider: "openai"`：任意 OpenAI 兼容接口（rememori 内置 `openai` embedder，`POST {baseUrl}/embeddings`），配 `memoryEmbedBaseUrl`（如百炼 `https://dashscope.aliyuncs.com/compatible-mode/v1`，留空则用 OpenAI 官方）+ `memoryEmbedApiKey` + `memoryEmbedModel`（如 `text-embedding-v4`）；启动时发一次最小 embedding 请求验证地址/密钥/模型。
- 两种提供方切换或换模型 = 旧向量全部失效，需删除 `memoryStorePath` 文件重新积累。

本项目刻意规避的已知短板：

1. `extractor: false`：内置实体抽取对中文无效，直接关闭实体图。
2. 不用 `reinforceFromOutput`：按空格分词，中文无法判定证据。
3. 只允许 Bot 主进程打开记忆文件：不要另起进程 / MCP Server 指向同一文件。
4. 换 `memoryEmbedModel` 等于全量重嵌入：需要删除旧文件重新积累，或写脚本按 `createdAt` 导入。
